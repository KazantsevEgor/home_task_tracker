### 2. Индивидуальный проект

**Название проекта:** Трекер домашних задач

**Реализованные изменения:**

Проект переработан с функционального подхода (список словарей) на объектно-ориентированный (список объектов `Task`).

**Класс Task (`models/task.py`):**

| Атрибут / Метод | Тип | Назначение |
|---|---|---|
| `id` | `int` | Уникальный идентификатор |
| `name` | `str` | Название задачи |
| `category` | `str` | Категория задачи |
| `deadline` | `str` | Дедлайн в формате ISO 8601 |
| `is_completed` | `bool` | Статус выполнения |
| `__init__()` | `→ None` | Конструктор объекта |
| `__str__()` | `→ str` | Строковое представление |
| `mark_completed()` | `→ None` | Отметить выполненной |
| `cancel_completion()` | `→ None` | Снять отметку |
| `get_status()` | `→ str` | Текстовый статус задачи |
| `days_until_deadline()` | `→ int` | Дней до дедлайна |
| `to_dict()` | `→ dict` | Сериализация в словарь |
| `from_dict()` | `→ Task` | Десериализация из словаря (classmethod) |

**Адаптированные модули:**

| Модуль | Изменение |
|---|---|
| `tasks.py` | Функции переведены на `list[Task]`; обращение к атрибутам объекта вместо ключей словаря |
| `completions.py` | Функции используют методы `task.mark_completed()` и `task.cancel_completion()` |
| `storage.py` | `load_tasks()` возвращает `list[Task]` через `Task.from_dict()`; `save_tasks()` сериализует через `task.to_dict()` |
| `main.py` | `show_tasks()` обращается к атрибутам объекта; используется `task.get_status()` |

### 4. Вывод

В ходе выполнения ПР3 проект «Трекер домашних задач» переведён с процедурного подхода на объектно-ориентированный. Данные задач теперь представлены объектами класса `Task`, а не словарями. Инкапсуляция данных и поведения в классе позволяет обращаться к свойствам задачи через атрибуты объекта и использовать методы объекта для изменения его состояния. Формат хранения данных (JSON) остался прежним: при загрузке словари преобразуются в объекты, при сохранении — обратно.
