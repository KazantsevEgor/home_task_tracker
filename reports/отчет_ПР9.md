## Доработка проекта

В приложении `task_pages` описаны две модели:

- `Category`: автоматический первичный ключ и уникальное название
  (`CharField`, до 200 символов).
- `Task`: автоматический первичный ключ, название (`CharField`), срок
  (`DateField`), признак выполнения (`BooleanField`, по умолчанию `False`),
  категория (`ForeignKey`).

Связь «один ко многим»: категория содержит задачи. Параметр
`related_name="tasks"` обеспечивает обратное обращение к задачам категории.
`on_delete=PROTECT` запрещает удалять категорию, пока у неё есть задачи.
Просрочка вычисляется по сроку и статусу задачи с учётом часового пояса проекта.

Создана и применена миграция `task_pages/0001_initial`. Использован перенос
в таблицы, управляемые Django, в `db.sqlite3`. Сначала сохранены резервные
копии исходной и целевой баз. Команда `python manage.py import_legacy`
перенесла 3 категории и 6 задач из `data/tracker.sqlite`. Сохранены ID,
значения полей и внешние ключи. Источник открывается только для чтения.
Перенос атомарен; повторный запуск допустим для совпадающих данных,
конфликт приводит к откату без перезаписи существующих записей.

Представления списка, карточки, активных задач, поиска по сроку и статистики
переведены на ORM. Добавлены поиск по названию и категории, фильтры статуса
и даты, четыре варианта сортировки, пагинация по 10 записей с сохранением
параметров. Некорректные даты, сортировки, номера страниц и отсутствующие
задачи обрабатываются. Карточка показывает до трёх других задач категории.

Используются `get`, `filter`, `exclude`, `Q`, `order_by`, `select_related`,
обратная связь, `values_list`, `aggregate`, `annotate`, `Count`, `Min`
и `Paginator`. В README приведён перечень 18 запросов и вариантов выборок.
Создание, редактирование и удаление доступны через Django admin; CRUD также
проверен на тестовых данных. Статистика включает категории без задач.
README обновлён: модели, миграции, перенос, запуск, команды проверки,
экспорт и загрузка fixture, примеры ORM для защиты.
