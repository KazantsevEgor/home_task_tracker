### 3. Доработка индивидуального проекта

#### 3.1. Структура базы данных

В предметной области одна сущность — задача, поэтому для связи таблиц категория задачи (в JSON — строка в каждой задаче) вынесена в отдельную таблицу. Получилось две таблицы: одна категория содержит много задач.

**`categories`**

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY` | идентификатор |
| `name` | `TEXT NOT NULL UNIQUE` | название категории |

**`tasks`**

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY` | идентификатор |
| `name` | `TEXT NOT NULL` | название задачи |
| `category_id` | `INTEGER NOT NULL`, `FOREIGN KEY → categories(id)` | категория |
| `deadline` | `TEXT NOT NULL` | дедлайн, формат `ГГГГ-ММ-ДД` |
| `is_completed` | `INTEGER NOT NULL DEFAULT 0`, `CHECK (is_completed IN (0, 1))` | 0 — не выполнена, 1 — выполнена |

Дедлайн хранится строкой в формате ISO, что позволяет сравнивать и сортировать даты средствами SQL.

#### 3.3. Создание базы и перенос данных

```
python -m db.import_json
```

Скрипт выполняет схему, очищает таблицы (сначала `tasks`, затем `categories` — из-за внешнего ключа), вставляет категории, затем задачи через `executemany` с параметрами `?`; при ошибке выполняется `rollback()`. Повторный запуск безопасен.

Проверка импорта: в `categories` 3 записи (Покупки, Ремонт, Уборка), в `tasks` 6 записей — по числу задач в `tasks.json`; запрос `JOIN` возвращает задачи с названиями категорий; `PRAGMA foreign_key_list(tasks)` показывает связь с `categories`.

В `data/tasks.json` к трём исходным задачам добавлены ещё три (в том числе с будущими сроками и третья категория «Ремонт»), чтобы запросы с фильтрацией и группировкой возвращали содержательные результаты.

#### 3.4. SQL-запросы (`sql/queries.sql`)

Все запросы выполнены в SQLite CLI (`sqlite3 data/tracker.sqlite < sql/queries.sql`), результаты проверены.

| № | Назначение | Вид |
|---|---|---|
| 1 | Список категорий | SELECT |
| 2 | Задачи по дедлайну, `LIMIT`/`OFFSET` | SELECT |
| 3 | Активные задачи | WHERE |
| 4 | Невыполненные задачи со сроком не позже даты | WHERE |
| 5 | Просроченные задачи | WHERE |
| 6 | Задачи с названием категории и признаком просрочки | JOIN |
| 7 | Одна задача по `id` | JOIN, WHERE |
| 8 | Задачи выбранной категории | JOIN, WHERE |
| 9 | Количество активных задач | COUNT |
| 10 | Сводка: всего, выполнено, просрочено | COUNT, SUM |
| 11 | Ближайший и самый поздний дедлайн | MIN, MAX |
| 12 | Количество задач по категориям | LEFT JOIN, GROUP BY |
| 13 | Категории с более чем одной задачей | GROUP BY, HAVING |
| 14 | Активные задачи по категориям | JOIN, GROUP BY |
| 15 | Ближайший дедлайн в каждой категории | JOIN, GROUP BY, MIN |
| 16 | Категории без невыполненных задач | подзапрос `NOT IN` |

Итого 16 запросов: выборок списков — 2 (№ 1, 2), с `WHERE` — 5, с `JOIN` — 7, с агрегатными функциями — 7, с `GROUP BY` — 4, плюс `HAVING` и подзапрос. Требование (не менее 10 запросов и не менее двух каждого вида) выполнено.

#### 3.5. Получение данных в Django-представлениях

`task_pages/views.py` выбирает данные из SQLite через `db.database.get_connection()` (`row_factory = sqlite3.Row`, поэтому в шаблонах поля доступны по именам) и передаёт строки результата в существующие шаблоны через контекст. Значения от пользователя передаются только параметрами `?`:

```python
fetch_one(TASK_SELECT + " WHERE tasks.id = ?", [task_id])
```

Признак просрочки `is_overdue` вычисляется в запросе, поэтому шаблон `task_status.html` работает и с объектами `Task`, и со строками результата SQL.

#### 3.6. Страницы и навигация

| URL | Что показывает | Запросы |
|---|---|---|
| `/tasks/` | список задач, фильтр по категории (`?category=`) | 1, 6, 8 |
| `/tasks/<id>/` | страница задачи, HTTP 404 для несуществующей | 7 |
| `/tasks/active/` | активные задачи | 3 |
| `/tasks/due/?date=` | поиск задач по сроку (форма с датой) | 4 |
| `/tasks/statistics/` | сводка, задачи по категориям, категории с несколькими задачами | 10, 11, 12, 13 |

Навигация (`templates/includes/navigation.html`): Главная | Задачи | Активные задачи | Статистика; ссылка «Найти задачи по сроку» размещена на странице списка. Все ссылки формируются через `{% url %}`. Некорректная дата в поиске по сроку отклоняется до обращения к базе; пустые результаты обрабатываются в шаблонах через `{% empty %}`.
