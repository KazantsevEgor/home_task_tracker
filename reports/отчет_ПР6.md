### 3. Доработка индивидуального проекта

**Структура шаблонов.** Создан каталог шаблонов уровня проекта `templates/` (параметр `DIRS` в `TEMPLATES` указывает на `BASE_DIR / 'templates'`) и каталоги `templates/` приложений:

```
templates/
├── base.html
└── includes/navigation.html
homepage/templates/homepage/index.html
task_pages/templates/task_pages/
├── task_list.html
├── task_detail.html
└── includes/
    ├── task_card.html
    └── task_status.html
```

**Базовый шаблон.** `templates/base.html` содержит общую структуру страниц: объявление документа, кодировку, Bootstrap, собственный CSS, логотип, навигацию, контейнер, подвал и подключение JavaScript. Блоки `{% block title %}` и `{% block content %}` переопределяются в дочерних шаблонах.

**Наследование.** Шаблоны `index.html`, `task_list.html`, `task_detail.html` начинаются с `{% extends "base.html" %}` и не дублируют общую структуру.

**Include.** Навигация (`includes/navigation.html`), карточка задачи (`task_card.html`) и статус задачи (`task_status.html`) вынесены во включаемые шаблоны. Статус используется и в списке, и на странице отдельной задачи.

**Контекст, циклы и условия.** View-функции передают данные словарём контекста (`{"tasks": tasks_list}`, `{"task": task}`). В шаблонах используются `{% for %}` с `{% empty %}` для пустого списка и `{% if %}` для статусов задачи и отсутствующей задачи.

**Именованные URL.** В `homepage/urls.py` задан `app_name = "homepage"`, в `task_pages/urls.py` — `app_name = "tasks"`; маршруты получили имена `index`, `list`, `detail`. Все ссылки в шаблонах формируются тегом `{% url %}`:

```django
{% url 'homepage:index' %}
{% url 'tasks:list' %}
{% url 'tasks:detail' task.id %}
```

**Фильтры.** `{{ tasks|length }}` — количество задач на странице списка; `{{ task.name|default:"Без названия" }}` — значение по умолчанию в карточке и на странице задачи.

**Статические файлы** (`homepage/static/homepage/`):

| Файл | Назначение |
|---|---|
| `css/style.css` | Собственные стили: карточка задачи, статус, логотип, подвал |
| `js/main.js` | Выводит текущий год в подвале |
| `img/logo.png` | Логотип, выводится в `base.html` |

Подключены через `{% load static %}` и `{% static %}`; Bootstrap сохранён.

**Изменения в Python-коде.**

- `homepage/views.py`: функция `page()` и `HttpResponse` удалены, `index()` использует `render()`.
- `task_pages/views.py`: HTML-строки удалены; view загружает данные, готовит контекст и вызывает `render()`. Для несуществующей задачи возвращается статус 404 (`status=404 if task is None else 200`).
- `models/task.py`: добавлено свойство `Task.is_overdue` (задача не выполнена, а дедлайн прошёл), чтобы шаблон выбирал цвет бейджа по состоянию объекта, а не по тексту статуса. `get_status()` использует это свойство, поведение не изменилось.
- Добавлены тесты: `tests/test_views.py` (7 тестов веб-страниц через тестовый клиент Django) и 3 теста для `Task.is_overdue`.

**Источник данных не изменился:** задачи загружаются из `data/tasks.json` функцией `storage.load_tasks()` в объекты `Task`. Django ORM не используется.

### 4. Результат работы

Реализованы страницы:

| URL | Шаблон | Что проверено |
|---|---|---|
| `/` | `homepage/index.html` | базовый шаблон, навигация, логотип, год в подвале |
| `/tasks/` | `task_pages/task_list.html` | цикл, карточки, `{% include %}`, фильтр `length`, бейджи статусов |
| `/tasks/<id>/` | `task_pages/task_detail.html` | данные задачи, именованные URL, возврат к списку |
| `/tasks/9999/` | `task_pages/task_detail.html` | сообщение «Задача не найдена», HTTP 404 |

HTML больше не формируется в `views.py`; схема обработки запроса: `view → context → template → HTML`. Обновлён `README.md`.
